# Paseo 0.9.0のサーバー側設定取得APIでZCodeパスの画面設定を許可する

## Context and Problem Statement

ADR 0008 では、Paseo 0.8.0 時点において「サーバー側からプラグイン設定値を読み出す公式 API が存在しなかった」ため、設定画面を読み取り専用の診断情報表示に限定し、カスタムインストール先の指定は daemon の環境変数 `PASEO_ZCODE_INSTALL` のみに委ねていた。
Paseo 0.9.0 で `server.registerSettings(definition)` が追加され、サーバー側サブプロセスで設定値を同期的に読み出す `read()` および変更監視 `subscribe()` が公式に提供された。また、クライアント側には `useSettings`、`<ExternalLink>`、`<SettingsInput>`、および複数接続先ホストを一覧取得する `useHosts()` が整備された。
これにより、ユーザーが環境変数を直接設定することなく、UI から直接 ZCode のカスタムインストール先を設定・永続化し、即時にプロバイダ起動や診断に反映できるようになる。

## Decision Drivers

- ADR 0008 で保留されていた「Paseo がサーバー側の設定読取 API を公開した場合の再検討」の条件が満たされた。
- 非標準パスに ZCode をインストールしているユーザーが、daemon の起動スクリプトや環境変数を編集せずに UI 上でパスを指定できるようにする。
- 優先順位の明確化：UI 設定値（`customInstallPath`）> 環境変数（`PASEO_ZCODE_INSTALL`）> 既定の OS 自動検出パス。
- トラブルシューティングや公式リソースへのアクセスを容易にするため、`<ExternalLink>` による外部リンク導線（公式サイト・リリースノート・Issue）を提供する。
- マルチホスト環境（`useHosts`）での稼働状態を診断画面で可視化する。

## Considered Options

- `defineSettings` と `server.registerSettings` を採用し、UI からカスタムインストール先を設定可能にする（採用）。
- 引き続き環境変数のみを維持し、UI 設定は提供しない。
- 独自の設定ファイル（`~/.config/zcode-provider.json` 等）を自前で実装する。

## Decision Outcome

Chosen option: "`defineSettings` と `server.registerSettings` を採用し、UI からカスタムインストール先を設定可能にする", because Paseo 0.9.0 公式の設定同期・永続化機構と完全に対合し、サーバー側の起動・検出パスとクライアント側の UI が安全かつシンプルに整合するためである。

1. `shared/settings.ts` でホストスコープの設定 `zcodeSettings`（`customInstallPath`）を定義。
2. `index.server.ts` で `server.registerSettings(zcodeSettings)` を呼び出し、設定ハンドラを取得。`provider` および診断 RPC ハンドラに `getCustomInstallPath` 関数として注入。
3. `server/discovery` および `server/provider` では、設定で指定されたパスが存在する場合はそれを最優先し、未設定の場合は環境変数 `PASEO_ZCODE_INSTALL`、それもなければ OS 既定のパスを採用。
4. `client/diagnostics.tsx` に `ConfigurationSection` を追加し、`useSettings` を通じてパスの保存・リセットを可能にする。保存後は自動的に診断を再実行して即時反映を確認できる。
5. 診断画面に `<ExternalLink>` による公式ドキュメント・Changelog・GitHub への導線を追加し、起動失敗時（`FailedView`）にも直接ダウンロードやトラブルシューティングへのアクセスを提供する。
6. `useHosts()` を利用して、複数ホスト接続時に各ホストの状態（online/connecting/error等）を一覧表示する。

### Consequences

- Good, because ユーザーが GUI の Settings 画面から ZCode のインストールパスを直接変更・リセットでき、環境変数設定の手間が解消される。
- Good, because サーバー側とクライアント側で Paseo 0.9.0 公式の `SettingsDefinition` を共有し、設定の二重管理や同期の不整合が発生しない。
- Good, because 未設定時は従来の自動検出および環境変数設定と完全な下位互換性が維持される。
- Good, because 外部リソース（公式サイト・Changelog・GitHub）への安全なリンクや、複数ホスト情報の可視化により利便性と保守性が大幅に向上する。

### Confirmation

- `server/status.test.ts` で設定由来のカスタムパスが優先され、診断結果に `installRootSource: "settings"` が返ることを単体テストで検証。
- `npm run typecheck`、`npm test`、`npm run build` の全通過。
- `scripts/check-upstream.mjs` による Paseo 0.9.0 上流連携テストで、`server.registerSettings` およびクライアント設定・UI コンポーネントが正常に動作することを検証。
